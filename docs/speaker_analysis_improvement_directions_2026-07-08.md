# 说话人分析准确率提升方向分析（2026-07-08）

基于对 `role_analyzer.py`、`BookVoiceParser/` 全流水线、`tools/evaluate_evidence_review.py`、`tools/audit_sample.py`、`review_packet.py` 以及 14 篇 docs/ 实验记录的通读，给出当前准确率瓶颈定位与可推进方向。

## 一、现状定位

| 场景难度 | agnes 完整流水线 | 强模型(claude fable)裸单遍 | 差距 |
|---|---:|---:|---:|
| 双人简单场景 (≤2人) | 95.0% | 97.87% | ≈0（已近天花板）|
| 密集多人场景 (≥3人) | 87.0% (seg8密集桶 82.5%) | 95.2% | **+9~13pp** |
| seg8 整体（7人，最难）| 84.40% | 93.62% | +9.2pp |
| + audit-safe 复核 (sensenova 分层阈值) | 89.36% | — | +4.96pp（方法侧）|

**一句话**：双人场景已到天花板，全部差距集中在**密集多人场景**；agnes 侧方法能再榨 +5pp，但换强模型能直接 +9~13pp。这是**能力级差距，不是方法级差距**。

## 二、瓶颈诊断

1. **错误高度集中在密集多人话轮翻转**。`flagging_audit_analysis` 显示 89 个人工确认错误中，"高置信错误几乎全是对话轮换/内心独白推理"——模型在叙述→对话衔接处**猜**，且自信。错误还会**链式传染**（seg9[154-157]、真唯外传[0-14]整段翻转）。
2. **置信度刻度失真**：conf=0.8 桶实际错误率(20.3%)反而高于 0.65 桶(12.8%)。置信度不是可靠信号，导致所有依赖置信度的下游门控（审计目标筛选、自动覆盖阈值）都受影响。
3. **同模型多意见共享盲区**：流水线/裸单遍/重问三方多数票建议正确率仅 2/17。agnes 系方法在"内心独白→对话"上系统性盲区，自己纠不到自己。
4. **复核器的真实价值是分歧检测，不是裁决**：异构模型(glm-5-turbo)当第二意见时，已知错误纠对率 81%、分歧捕获率 86%，远超同构(44%/65%)。

## 三、已被证伪、不应重试的方向

这些方向都已有明确的负结果记录，避免重复投入：

| 方向 | 结果 | 出处 |
|---|---|---|
| 场景摘要/身份事实注入复核 prompt | 强复核器下 −1~−3pp，无收益 | scene_brief_experiment_sensenova_2026-07-08 |
| block_review 保守模式 | seg8 −12.8pp，永久休眠 | flagging_audit_analysis 4.9 |
| 单遍初判替代分批 | 净负，block_review 依赖分批状态 | flagging_audit_analysis 4.7 |
| 上下文宽度 320→960 | 初判几乎不变、流水线反降 4pp | flagging_audit_analysis 4.5 |
| 归属约定塞进流水线长 prompt | 稀释核心轮换判断，净负 | flagging_audit_analysis 4.8 |
| 同模型三方多数票自动改判 | 共享盲区，2/17 正确 | flagging_audit_analysis §3 |
| speaker_verification 默认开 | 过度纠正多于修复 | role-analysis-optimization-handoff |

**共同教训**：在弱模型(agnes)上做 prompt/策略微调的收益已趋于饱和；长 prompt 加规则会产生**稀释效应**。短任务的审计重问里有效的约定，塞进长系统提示反而适得其反。

## 四、可推进方向（按预期 ROI 排序）

### A. 模型 / 路由层（最高 ROI，直接攻唯一瓶颈）

**A1. 密集场景路由到强模型** ★最高优先级
- 依据：强模型在 seg8 密集桶 95.2% vs agnes 82.5%，+12.7pp。简单场景 agnes 已 95%，强模型无增量。
- 做法：检测场景密度（±4 窗口内 ≥3 个具名说话人，约占 25% 段），只把这些 block 送强模型（claude/GLM/deepseek-v4）做单遍归因 + 归属约定，其余仍走 agnes。
- 成本可控：只有 1/4 的段走付费模型。性价比远高于全量替换。
- 落地点：`BookVoiceParser/parser.py` 的 block 调度处加密集度判断 + 强模型分支；或新建 `dense_router.py`。

**A2. 异构模型接管审计重问**
- 依据：glm-5-turbo 异构重问错误纠对率 81% vs agnes 同构 44%；分歧捕获 86% vs 65%。
- 做法：把 `audit_sample.py` 的 reask 模型从 agnes 换成异构（已支持 `--hetero`），并默认开启。只扫 agnes 各路一致的段（约 60-110 次/样本），额度全花在同构盲区上。
- 落地点：`BookVoiceParser/audit.py` + `tools/audit_sample.py` 默认异构。

### B. 审计 / 证据层（中 ROI，承接今日工作）

**B1. 生产级目标发现策略**（摆脱 oracle）
- 现状：audit-safe 在 oracle/audit-disagree 上验证过，但生产没法用真值挑目标。
- 做法：多信号交集选目标 —— 弱证据标签(`dialogue_alternation/narrator_anchor/scene_presence/address_term`) ∪ 审计第二意见分歧 ∪ confidence<0.7(校准后) ∪ 密集场景 ∪ 候选/称呼冲突。`evidence_based_review_workflow` 已列出该清单，需落地为 `target-mode production`。

**B2. address_term 硬门控**
- 依据：身份事实注入会增加 address_term 误伤；`address_term_backcheck.py` 已存在但未接入自动覆盖门控。
- 做法：在 `evaluate_evidence_review.py` 的 auto-apply 门控里加规则：被称呼者不能直接当说话人，除非 reason 含后文明示/第一人称/动作主语。或把 address_term 阈值提到 0.90。

**B3. 降低 uncertain 比例**
- 现状：今日 sensenova 复核 45 个目标里 uncertain 7~17 个，纯损失。
- 做法：先逐条归类 uncertain 案例（是证据不足还是模型骑墙）；对高信号反证类型(explicit_after/first_person)允许更低阈值强制决策；其余 uncertain 路由人工队列或第二轮异构复核。

**B4. 错误链式传染检测**
- 依据：错误会向 ±1 邻段扩散。
- 做法：当某段被 revise，对其前后邻段用新 speaker 作上下文重审一次。这是确定性后处理，无模型成本，专门捞链式翻转。

### C. 初判 / 流水线层（ROI 较低，负面结果多但根因未解）

**C1. 置信度重校准** ★基础性工作
- 依据：当前置信度失真(0.8 桶比 0.65 桶错更多)，所有下游门控都受拖累。
- 做法：在 5 个标注样本上做 isotonic/分桶校准，或用证据标签+场景密度训练一个轻量错误概率预测器替代原始 confidence。校准后 A1/B1 的阈值才有意义。

**C2. Trap-B 后置叙述线索的两遍解码**
- 依据：handoff 记录 trap-B（后置叙述揭示真实说话人）在线索距台词 3+ 行时失效。
- 做法：compact 解码后加一遍确定性扫描——找"X 挥手/否定/笑道"这类主语动作行，回溯到其前最近的对白行并归给该主语。无模型成本。

**C3. 跨批状态连续性**（根因仍开放）
- 分批初判(85.1%)弱于裸单遍(92-97%)，嫌疑是跨批状态丢失。但单遍初判替代(净负)和上下文加宽(净负)都失败，说明不是窗口大小问题，而是**状态结构**问题。
- 做法：改进 batch 间传递的状态——不只传 active_speakers，还传"当前话轮相位/上一句实际说话人/待回应对象"，作为结构化上下文而非自然语言摘要。风险较高，建议在 A1 之后做。

### D. 评测基础设施（使能器，不直接提分但解锁后续）

**D1. 扩充跨类型基准**
- 现状：5 个 muli4 样本 + 真唯外传，全部来自《魔弹之王》系。所有结论都建立在一本书的风格上，跨类型泛化未知。
- 做法：补 2-3 本不同风格（现代都市/古风/玄幻）的标注样本，验证 A1 路由和 audit-safe 是否过拟合 muli4。

**D2. 回归仪表盘**
- 现状：per-sample 数据散落各 doc。
- 做法：单一 dashboard 跟踪 每方法×每样本×每错误类型的 修对/误伤/仍错改判。今天 work_status 提到的"audit-safe 接入复核包 UI"是子集。

**D3. 自动化测试**
- README 明确"当前没有自动化测试"。给 BookVoiceParser 核心模块补 pytest + 夜间 5 样本回归，防回归。

### E. 产品化 / 工程

**E1. audit-safe 输出接入复核包 UI**：展示 speaker / 建议 speaker / counter_evidence_type / baseline_evidence_valid / auto_apply_safe / reason（work_status 已列）。
**E2. 别名/身份预解析一等公民**：identity_alias 是独立反证类型，moon/帕曼/琴纱月混淆是已知痛点。做按书确认的别名注册表预解析，消除整类错误。
**E3. evaluate_evidence_review 批量 404 重试**：今日 RUN1 第9批遇 404 静默漏 3 目标，加指数退避重试。

## 五、建议推进顺序

```
第一阶段（攻瓶颈）：A1 密集场景路由 → A2 异构审计重问
   预期：seg8 密集桶 82.5% → 90%+，整体 84.4% → 91%+
第二阶段（夯门控）：C1 置信度校准 → B1 生产目标发现 → B2 address_term硬门控 → B4 链式检测
   预期：自动覆盖从"保守捞1条"提升到稳定多捞且0误伤
第三阶段（防过拟合）：D1 跨类型基准 → D2 仪表盘
第四阶段（收尾工程）：E1 UI接入 / E2 别名预解析 / E3 重试
```

**核心判断**：项目在 agnes 弱模型上做了大量方法实验，边际收益已递减且出现多个负结果。下一步的实质性跃迁来自**把贵的 token 精准花在 agnes 最弱的密集多人场景上**（A1）和**用异构模型补同构盲区**（A2）——这两点都有明确正向数据支撑，且成本可控。audit-safe 门控优化（B 组）是承接今日工作的近期抓手，但天花板受限于复核器模型本身。
