## 1. 错误集与阶段归因

逐段对照原文，确认 **≥43 处归因错误**（书签 42 + 原文复核新增 1，且实验又暴露至少 3 处漏网，
见 §3）。按"是哪个阶段造成的"归因（依据快照里每段的 evidence）：

| 阶段 | 错误数 | 说明 |
|---|---:|---|
| **LLM 分批初判**（轮换/独白/密集推理） | **29** | 主体。叙述→对话衔接处用"轮换/内心独白"猜测，且常自信（与 0610 文档第 2 节"高置信错误共性"一致） |
| **address_term_backcheck**（称呼反推/关系称谓） | **8** | 其中「姐姐→甘织遥奈」局部反推**净创造 4 处错误**（428/431/455/530），是纯回归 |
| narration→具名 / 其他 | 4 | 324(旁白挂真唯)、400、671、682 |
| block_review | 1 | 228（话轮相位错一格） |
| LLM 未返回(conf0.2) | 1 | 281 |

**两个结构性根因（可定位到代码）：**

### 根因 A：角色清单/别名从未结构化喂给模型
`batch_llm_attributor.py` 只给模型**每条台词的 candidates 列表**（来自 candidate_gen）+ 320 字窄窗，
**没有**完整角色表与别名映射。后果：
- 「玲奈子同学」「纱月同学」「真唯」这类**称呼**被当成说话人 → 310/318/325/556/604/661/367/651；
- 新角色**照泽耀子**在自我介绍句（「我是照泽耀子」）未被 candidate_gen 注册 → 她整段台词被分给
  高田卑弥呼或玲奈子（310/314/318/325）；
- 别名未归一（候选里同时有「玲奈子同学/小玲奈子/甘织」等）增加歧义。

### 根因 B：`address_term_backcheck._apply_relation_vocative_backcheck` 过度触发
（`BookVoiceParser/book_voice_parser/address_term_backcheck.py:467`）
逻辑：叙述者(玲奈子)台词只要**子串**含「姐姐/哥哥」，就改判给"最近的非叙述者"。问题：
1. 不区分**称呼**（「姐姐，早安」）与**词语使用**（「玩扮演**姐姐**游戏」「**作为姐姐**」「叫我**姐姐**」）
   —— 428/455/530 全是后者被误改；
2. 改判目标**不校验是否在当前场景**（scene_state 已知却没接入）——把玲奈子的台词改给了根本不在场的遥奈。

### 根因 C：scene_state 跨场景泄漏
纱月登门场景原文只有玲奈子+纱月（玲奈子称对方「纱月同学」），但 `scene_characters` 把
**王冢真唯**带了进来，导致 554/558/560 被判给真唯（真唯全程不在场）。这 3 处此前漏网，由实验暴露。

## 2. 改进实验（agnes-2.0-flash，整场重问 A/B）

在 7 个错误密集场景（185 个对话行、含 37 处已知错误）上三路对比：

| 方案 | 总体准确 | 修复已知错误 | 误改原本正确 |
|---|---:|---:|---:|
| **P** 流水线原始输出 | 80.0%（构造性下限） | 0/37 | 0 |
| **B** 整场重问·**无清单** | 58.4% | 26/37 | 66 |
| **T** 整场重问·**清单+规则** | 73.5% | **31/37** | 43 |

T 的规则 = 角色表+别名映射 + ①称呼≠说话人（含「X同学/小X/姐姐」）②自我介绍「我是X」→X
③只在本场景在场者中选 ④第一人称无引号叙述→旁白 ⑤注意轮换。

**结论（关键，不能只看总体分）：**
1. **T 把整类根因 A/B 错误几乎全修了**：照泽耀子注册(310/314/318/325)、姐姐→遥奈回归(428/431/455/530)、
   称呼陷阱(556/604/661/367)、不在场真唯/纱月(590/604/671/672) —— 共 31/37。证明"结构化角色表 +
   称呼/场景规则"正中主因。
2. **T 的 43 处"误改"被证实部分是 P 本身的漏网错误**：抽查 554/558/560（真唯不在纱月场景）T 改为
   玲奈子是**对的**，是我的对照集（=P 输出）不完整。即 part_001 真实错误数 >43，T 实际准确率被低估。
3. **但整场重问会动摇双人轮换**：无显式说话标签的纯轮换处（359/368/370 等）T 会整体相位翻转。
   **所以不能拿整场重问做无脑自动替换**（B 尤其灾难，58%）——这与 0610 文档"同模型重问只分流不裁决"
   一致：T 适合做 **tier1 第二意见/分歧检测**，而非直接改写。

## 3. 改进建议（按性价比排序）

1. **【最高杠杆·低成本】把结构化角色表+别名映射注入初判 prompt**。当前模型看不到全局角色表；
   注入后可一次性压制称呼陷阱、新角色漏注册、别名不归一。实验中这是 T 相对 B 提升 15pp 的主因。
   配套：candidate_gen 命中「我是X/我叫X」自我介绍时强制把 X 加入候选并置高权重。

2. **【纯赚·低风险】给 `_apply_relation_vocative_backcheck` 加两道闸**：
   (a) 命中的「姐姐/哥哥」必须是**真称呼**（句首「姐姐，」「姐姐！」或紧邻呼语），排除
   「扮演/当…的/作为+姐姐」等用法；(b) 改判目标必须**∈ 当前 scene_characters**。仅此可消除
   428/431/455/530 四处纯回归，零额外调用。

3. **【中】收紧 scene_state 的角色进/出**：场景切换（旁白出现新地点/新登场）时清退上一场景人物，
   避免王冢真唯泄漏进纱月场景（554/558/560 类）。

4. **【中】候选打分加"受话人排除"**：台词含「X同学/小X」呼语时，对 X 作为**说话人**降权
   （prompt 已有 addressee_trap 检测，但仅靠窄窗；配合根因 A 的全局别名表更稳）。

5. **【实验】整场重问改作 tier1 第二意见**：把 T（清单+规则）接入 `audit_sample.py` 的异构第二意见位
   （与 glm-5-turbo 同位），只在与流水线分歧处提示人工，**不自动改写**——避开双人轮换翻转，又能捞回
   根因 A/B 这类系统性错误。

6. **【验证 0610 的头号悬念】裸单遍初判 + 角色表**：T 的成功几乎全在**跨批/整场上下文**才能看出的错误
   （轮换相位、不在场人物、新角色），正对应 0610 文档"分批初判显著弱于裸单遍"的开放问题。建议把
   "裸单遍直出 + 角色表注入 + block_review"作为下一组消融，对照现行分批初判。

## 3.5 落地与验证（2026-06-14 补充）

实现了建议 1（角色表注入）+ 建议 2（关系称谓反推加闸），并用真实代码做了 A/B。

**改动：**
- `batch_llm_attributor.py` `_build_prompt/attribute(_batch)`：新增 `role_aliases` 参数，注入
  「别名映射 + 称呼判定规则」；`parser.py` 从既有 `AliasRegistry` 反推规范名→别名表传入。
  无 `role_aliases` 时完全不改 prompt（向后兼容）。
- `single_pass_attributor.py`：同样注入别名表 + 称呼/旁白规则（整文阅读路径）。
- `address_term_backcheck.py` `_apply_relation_vocative_backcheck`：加两道闸——
  ①`_is_elder_vocative()` 要求「姐姐/哥哥」是真呼语（排除「扮演/作为/的…姐姐」名词用法）；
  ②改判目标须 ∈ 当前 ±2 段 `scene_characters`。单测 8/8 通过；合成场景验证："扮演姐姐·遥奈
  不在场"不再误改、"真呼语·遥奈在场"仍正确改判。**428/431/455/530 四处纯回归被消除。**

**关键 A/B 结论（同评测集 185 对话行，含实验暴露的 554/558/560；真实代码路径）：**

| 方案 | 总体 | 修复已知错误 | 误改原本正确 |
|---|---:|---:|---:|
| P 流水线原始输出（完整流水线） | **78.4%** | 0/40 | 0 |
| 真实分批 `attribute()`·无清单 | 70.3% | 27/40 | 42 |
| 真实分批 `attribute()`·注入清单 | 69.7% | 26/40 | 42 |
| 单遍直出（整文阅读）·无清单 | 76.2% | **36/40** | 40 |
| 单遍直出（整文阅读）·注入清单 | 76.8% | **36/40** | 39 |

**两条经得起验证的结论（其余是噪声）：**

1. **真正的杠杆是上下文宽度，不是角色表**。单遍整文阅读修复 36/40 已知错误，分批窄窗只修 27/40
   —— 对"跨句轮换 / 在场人物 / 新角色自我介绍"这些病根，让模型一次看到整段才是关键。这正坐实
   0610 文档"分批初判弱于裸单遍"的判断，病根 = **分批 320 字窗丢了跨句轮换/在场信息**。
2. **角色表注入的边际增益很小**（分批 27→26、单遍 36→36）。⚠️ 自我修正：§2 那版"+15pp"是拿
   清单 prompt 对比一个**故意极简**的 baseline 得来的；一旦 baseline 本身已含"叙述者+归属约定"
   （单遍 prompt 即如此），再加别名表几乎不动指标。**建议 1 不是错，但别指望它单独提分**——它的价值
   在归一化输出名 + 兜底新角色，属卫生性改进。

另一条硬约束：所有"**从零重判 + 整体替换**"（分批/单遍）对照完整流水线 P(78.4%) 都更差（70–77%，
误改 39–42）——重判丢了 block_review 等下游纠错，并会翻转双人轮换。**故单遍/角色表重问只能作
tier1 第二意见（仅在与流水线分歧处提示人工），不可自动改写**。

**据此修订建议优先级：**
- 建议 2（关系称谓加闸）：**已验证净赚**，保留。
- 建议 1（角色表注入）：已实现、向后兼容、卫生性改进，但**单独不提分**；其正确落点是配合
  **单遍直出**（`first_pass="single"`，已注入）而非现行分批。
- **新的头号动作**：把"单遍直出初判"从实验位转正、或把分批窗口显著放宽到**整场/整对话块**，
  并把单遍输出接成 tier1 第二意见。这才是 36/40 vs 27/40 指出的真问题。

## 3.6 两个后续落地（2026-06-14 补充）

按上节结论，把"角色表重问只作 tier1 第二意见、不自动改写"真正接进工具，并补回归测试。

### A. 关系称谓加闸的正式单测 → `tools/test_relation_vocative_gate.py`
纯本地、无 API。覆盖：呼语真值表（4 非呼语 + 4 呼语）、"扮演姐姐·遥奈不在场"不改判、
"真呼语·遥奈在场"仍正确改判遥奈。**4/4 通过**，锁死 428/431/455/530 这类纯回归不复发。

### B. 单遍直出第二意见接入审计 → `audit_sample.py --singlepass`
新增 `--singlepass`：整文阅读 + 角色表注入，一次性归因，**与流水线分歧即入 tier1**
（强信号、按 P1/P2 优先级排序），**suggest-only：只读 parse，绝不改写 speaker**。
与既有 `--hetero`（glm-5-turbo）并列，可叠加。

**part_001 验证（`tools/test_singlepass_secondopinion.py`，185 对话行 / 40 已知错误）：**

| 指标 | 值 | 对照 |
|---|---:|---|
| 召回（旗到的已知系统错误） | **39/40 = 98%** | 旧 ⚑ 规则 recall 84% |
| 精度下界 | 39/77 = **51%** | 旧 ⚑ 规则 precision 13% |
| 流水线 speaker 被改写 | **0（suggest-only 已断言）** | — |
| 漏旗 | 仅 [465] | — |

即：**单遍第二意见能把 98% 的系统性错误以 tier1 旗标交给人工，且不动流水线一字**。精度
51% 是下界（"误报"里含 554/558/560 这类未登记的真错误，真实精度更高），已远优于旧 ⚑ 规则，
与 0610 文档的 hetero/tier1（21–28%）同量级或更好。代价是本错误密集子集上旗了 42% 的行——
正常样本错误率低，旗标率会随之下降。

**结论**：建议 5 兑现——"单遍直出+角色表"作 tier1 第二意见是高召回、零破坏的可用方案；
配合建议 2 的加闸（消除 4 处纯回归），二者均已落地 + 验证 + 测试。

## 3.7 群组聊天/剧本格式节修复（2026-06-14 补充）

**问题**：part_001 的外传节『五女神的房间』以「说话人：台词」逐行脚本格式书写、无「」引号
（女王/姬百合/miki 等昵称作行内显式标签）。这本是**最明确**的说话人信息，却因为引号驱动的
提取 + `_clean_narrator_text` 把空行并成空格，整块被吞成**单个旁白段**（q0206_n1），26 行台词
全部丢失说话人。

**修复**：新增 `script_block.py` + 接入 `_parse_with_batch_llm`（block_review 之后、密集路由之前）：
- `is_script_block()`：一段旁白里出现 ≥3 个"短名+冒号"行内标签、且冒号后不接「（排除
  「某某：「台词」」引用式）才判定为脚本块——普通散文/引用式不误伤（单测覆盖）。
- `apply_script_block_split()`：把脚本块切成逐行段，标签按 `AliasRegistry` 归一
  （女王→高田卑弥呼、姬百合→羽贺铃兰、miki→根本美姬），前言（如「（4）其之一」）→旁白；
  只动旁白/未知段，不碰已归因的对白。`attribution_type=explicit_before`、conf 0.95。

**效果**（实测该块）：1 段 → 27 段，26 行台词正确归属
**高田卑弥呼×15 / 羽贺铃兰×6 / 根本美姬×5**，前言 1 段旁白，头部「五女神的房间」未被动。
单测 `tools/test_script_block_split.py` 4/4 通过（含散文/引用式/单冒号不误切）。

> 已知边界：若某书将脚本行以空行**保留**为多个独立旁白段（而非并成一块），当前 `is_script_block`
> 按单段 ≥3 标签判定会漏掉——本卷 `_clean_narrator_text` 会并块，故此处命中；跨段脚本检测留待需要时再加。
