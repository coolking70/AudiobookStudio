# 密集多人场景 · 强模型复核（MCP）使用说明

## 这是什么 / 为什么

说话人归因里，普通双人对话自动准确率已约 **96.7%**；缺口几乎全在**密集多人场景**
（局部 ≥3 人同框的寒暄/问候，约占台词 24%、却占 63% 的错误）。评测显示：换一个**更强的
模型**、用同一套结构化方法重判这些片段，可把密集场景从 ~82% 提到 **~90%**，且模型档位影响
很小（haiku≈sonnet≈opus）。

主管线已经做了两件事来承接它：
- **自动路由**：把密集场景句压到复核阈值以下、进复核队列（`parse_novel(dense_scene_review_size=3)`，默认开）。
- **MCP 复核服务器**：把"密集场景重判"做成 MCP 工具，由**你自己的 MCP 客户端**（Claude Code/Desktop）
  里的强模型来执行——**不需要也不会暴露任何强模型 API key**。

## 前置条件

- 已安装可选依赖：`pip install "mcp[cli]"`（见 `requirements.txt`）。
- 一个 MCP 客户端，例如 **Claude Code**（命令行 `claude`）或 Claude Desktop。

## 操作步骤（端到端）

1. **跑分析**：在网页粘贴原文 → 执行 BatchLLM 分析，得到带说话人的结果。
2. **启动服务器**：在结果区展开 **「强模型复核（MCP）— 密集多人场景」** 面板，点
   **「启动 MCP 复核服务器」**。页面会显示一个 SSE 地址，形如
   `http://127.0.0.1:8970/sse`，并给出可复制的接入命令。
3. **接入客户端**：在终端运行面板给出的命令（以 Claude Code 为例）：
   ```
   claude mcp add audiobook-review --transport sse http://127.0.0.1:8970/sse
   ```
4. **让智能体复核**：在客户端里说一句，例如
   > 复核当前任务的密集场景。
   它会自动：`list_dense_scenes`（取回带标记的密集片段+方法，**不含答案**）→ 按方法重判 →
   `submit_attributions` 写回结果。
5. **导入结果**：回到网页，点面板里 **「导入复核结果」**，把强模型的判断应用到当前任务
   （更新对应句的说话人）。
6. **停止**：复核完点 **「停止」** 关掉本地服务器。

## 智能体侧用到的工具

| 工具 | 作用 |
|---|---|
| `list_dense_scenes(sample="current")` | 返回当前任务的密集片段（带 `【current_i】` 标记）+ 复核方法；不含真值 |
| `submit_attributions(sample, {tag: speaker})` | 写回 `{标记: 说话人}`；生产环境只持久化修正（无真值不打分） |
| `list_samples()` | 任务模式返回 `current` |

复核方法（已内置在 `list_dense_scenes` 返回里）：先读旁白定在场人物与登场顺序 → 收敛实际
参与者 → 逐句判断续说/交替/第三人/多对一 → 用称呼·口癖·语气·语义邻接·排除法校正。

## 说明与排错

- **隐私**：强模型由你的客户端提供，服务器只暴露原文片段，不外传任何密钥；开发样本的人工真值
  只在服务器端用于打分，不发给智能体。
- **端口**：默认 8970，被占用时自动顺延探测；面板显示实际地址。仅绑 `127.0.0.1`（本机）。
- **阈值**：密集判定为"局部 ±4 窗口内 ≥3 个具名说话人"；后端可调 `dense_scene_review_size`
  （设 0 关闭自动路由）。
- **导入无内容**：说明智能体尚未 `submit_attributions` 或本次无改动；确认客户端已连上并完成提交。
- **连不上**：确认 `mcp[cli]` 已装、服务器面板显示「运行中」、命令里的地址与面板一致。
