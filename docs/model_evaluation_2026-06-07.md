# 2026-06-07 模型评测记录

本文记录围绕第四卷前一小时样本进行的说话人归因模型评测。评测目标是比较 BatchLLM 主分析、复核模型、旧分析流程在同一组人工标注错误样本上的效果。

## 样本与口径

- 原文样本：`docs/samples/muli4_part001_first_hour_sample.txt`
- 书签回归样本：`docs/samples/muli4_part001_first_hour_bookmark_regression.json`
- 人工校正目标：30 条播放器书签定位到的说话人错误样本
- 总准确率：按 30 条全部样本计算
- 匹配准确率：只按能在当前分析结果中匹配到原文文本的样本计算

旧流程会改写或重组文本，因此额外统计了近似匹配；BatchLLM 相关流程以精确文本匹配为主。

## 主要结论

1. 当前最值得作为主 BatchLLM 初析模型的是 `deepseek-v3.1-terminus`，在交叉矩阵中达到 23/30，耗时约 128 秒，速度和准确率比较均衡。
2. `glm-5-turbo` 的初析最高记录为 23/30，但吞吐波动较大，另一轮交叉矩阵中为 22/30，耗时约 599-755 秒。
3. `deepseek-v4-pro-202606` 作为复核模型很强，返回样本中 24/25 正确，但做全文初析只有 19/30 且耗时约 872 秒。
4. 复核阶段目前不应自动覆盖。多组交叉测试中，复核模型几乎没有带来净提升，反而经常误伤姐妹对话、同学双人对话等长轮次场景。
5. BatchLLM 之前的旧分析流程不适合当前小说样本：BVP 纯规则只有 7/30，旧 `role_analyzer` 组合流程精确匹配 0/30，近似匹配也只有 5/30。

## 推荐配置

- 主 BatchLLM 初析：优先 `deepseek-v3.1-terminus`
- 备选初析：`glm-5-turbo`，适合可接受较长耗时的场景
- 复核辅助：`deepseek-v4-pro-202606` 或 `glm-5`
- 自动覆盖：保持关闭，仅写入建议证据或进入人工复核
- 旧流程：不建议作为当前项目的小说说话人归因主路径

## 复现实用脚本

- `tools/evaluate_tokenhub_models.py`：批量评估 TokenHub 模型复核能力
- `tools/evaluate_cross_model_parse_review.py`：评估单个初析模型与复核模型组合
- `tools/evaluate_cross_review_matrix.py`：解析一次后交叉多个复核模型
- `tools/evaluate_legacy_analysis_methods.py`：评估 BatchLLM 之前的旧分析流程
- `tools/build_bookmark_regression_sample.py`：从播放器书签生成回归样本
- `tools/check_bookmark_regression.py`：检查当前快照在书签样本上的命中情况
