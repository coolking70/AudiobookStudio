# A1 密集场景强模型路由验收（2026-07-11）

## 测试范围

- 冻结样本：`muli4_seg8`
- 基线：已提交 Agnes 解析快照
- 基线准确率：119/141 = 84.40%
- 基线简单场景：15/15 = 100.00%
- 基线密集场景：104/126 = 82.54%
- A1 晋升要求：密集场景至少 90%，整体不下降，简单场景不增加误伤
- 密集路由目标：124 段

所有模型在测试前均通过 `/models` 和最小 chat-completions 连通性检查。阿里云和 LongCat 域名在当前网络环境解析为私网出口，因此只在测试进程中显式设置 `AUDIOBOOKSTUDIO_ALLOW_PRIVATE_REMOTE_URLS=1`；没有修改生产默认安全策略。

## 结果

### 阿里云 `qwen3.5-35b-a3b`，生产 SPC 逐条策略

- 124 个目标全部完成，失败 0
- 耗时 649.687 秒（约 10.8 分钟）
- 自动改判 19，安全门控阻止 39
- 修对 3，误伤 12，净收益 -9
- 最终整体：110/141 = 78.01%
- 最终简单场景：15/15 = 100.00%
- 最终密集场景：95/126 = 75.40%

结论：相对基线整体下降 6.39 个百分点，密集场景下降 7.14 个百分点。主要误伤来自模型把对话轮换、语义接话和场景中出现的人物当成说话人；模型给这些建议 0.85–0.95 的高置信度，现有候选来源门控无法可靠区分。

### 阿里云 Batch 上下文对照

- 相同 124 个目标，batch size 8
- 运行超过 1,204 秒后超时
- 未产生完整可评分产物

结论：即使质量未知，也不满足当前 A1 的时延/成本要求。

### LongCat `LongCat-2.0`，生产 SPC 逐条策略

- 相同 124 个目标
- 运行超过 1,204 秒后超时
- 未产生完整可评分产物

结论：短连通性请求约 1 秒的延迟不能代表完整 SPC 提示吞吐；当前逐条方案不适合直接全量路由。

## 验收结论

A1 **未通过效果验收，不得默认启用**。代码接入和 UI 仍保留为实验开关，但当前没有符合“密集 ≥90%、整体不下降”的模型/策略组合。

下一轮开发必须先完成：

1. 将路由目标从“全部密集片段”收紧为密集场景与生产风险信号的交集，不能因密集场景统一降置信度而把全部段送审。
2. 强模型建议不得仅凭轮换、语义接话或 `role_hints/scene_active` 自动覆盖；需要结构化反证类型与独立说话证据。
3. 评测执行增加逐批进度、检查点和断点续跑，超时不能丢失已完成调用。
4. 在 `muli4_seg8` 上先达到零净误伤并改善密集准确率，再扩展到全部权威样本。
